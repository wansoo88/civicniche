# 13-A 랜딩 — UI 디자인 브리프

> 이 문서는 **"클로드, 이 랜딩 디자인 개선해줘"** 라고 할 때 컨텍스트로 쓰는 브리프다.
> 대상 파일: `index.html`(영문, root) · `index.ko.html`(국문, /ko/). 라이브: https://data.utilverse.info
> 작업 시작 전 **§5 깨면 안 되는 계약**을 반드시 먼저 읽을 것.

---

## 1. 이 페이지가 뭐냐 (맥락)
- **목적:** "정제 FDA 의료기기 계약제조사 데이터를 $29~99에 살 사람이 있나"를 빌드 전에 검증하는 **수요 검증 랜딩**(§13-A). 결제 안 받음 — 의향(샘플요청/사전구매)만 수집.
- **단계:** 정식 출시 전(pre-launch). 화려한 제품 사이트가 아니라 **신뢰가는 1인 데이터 벤더의 깔끔한 랜딩**이어야 함.
- **브랜드:** Utilverse Data (도메인 utilverse.info).
- **트래픽 출처:** SEO 아님. Datarade·Kaggle·Reddit(r/datasets, r/medicaldevice)·LinkedIn·콜드아웃리치 → **직접 링크로 도착**. 즉 첫인상 1스크롤이 전환을 좌우.

## 2. 타깃 & 톤
- **독자:** 영어권 B2B — 의료기기 소싱/조달, 규제·QA 컨설턴트, 리드브로커, 데이터 개발자. (한국어판은 KC/RRA 2차 신호용)
- **톤:** 직설적 founder-voice. 마케팅 버즈워드("unlock/seamless/leverage")·이모지 남발·과장 금지. **AI가 쓴 티 안 나게.** 약점도 정직하게 노출하는 게 오히려 신뢰를 높임("Can't I just pull this myself? You can —…").
- **핵심 신뢰 장치:** ① 무료 25행 샘플 먼저 ② 출처 명시(openFDA, CC0) ③ 한계 정직 고지.

## 3. 현재 상태 (정직한 평가)
- 순수 정적 HTML/CSS(프레임워크 없음), 시스템 폰트, 단일 컬럼 720px, 카드형, 파란 액센트(#1d4ed8).
- **장점:** 빠름, 가벼움, 깨끗함, 접근성 무난.
- **약함(개선 여지):**
  - 히어로가 텍스트만 — 시각적 후킹 약함. 첫 화면에서 "뭘 파는지/왜 신뢰?"가 더 즉각적이어야.
  - CSV 미리보기(검은 `<pre>`)가 좁은 화면에서 가로 스크롤, 가독성 낮음. → "데이터가 진짜다"를 보여주는 핵심 요소인데 푸대접.
  - 가격 표시가 한 줄 텍스트 — 3티어(스냅샷/구독/API) 비교가 한눈에 안 들어옴.
  - 신뢰 요소(출처 배지, "no personal data", CC0, 갱신주기)가 푸터에만 묻힘 → 위로 끌어올릴 가치.
  - favicon·OG/트위터 메타·소셜 프리뷰 이미지 없음 → 링크 공유 시 미리보기 빈약(아웃리치에 직접 영향). **(개선 1순위)**
  - 폼이 길어 보임 — 첫 전환 마찰. 이메일+버튼만 먼저, 나머지는 점진 노출 고려.

## 4. 개선 방향 (우선순위)
1. **소셜 공유 메타 + favicon** — `og:title/description/image`, `twitter:card`, favicon. 아웃리치 링크 클릭률에 직결. (가장 ROI 높음)
2. **히어로 강화** — 한 줄 가치제안 + 즉각적 신뢰 신호(출처 "openFDA · CC0" 배지, "~65,000 records", "1 row per manufacturer"). 시각적 위계 강화.
3. **CSV 미리보기 개선** — 실제 표(HTML table)로 보여주거나 가로 스크롤 깔끔하게, 컬럼 강조. "데이터 진짜다" 증거물이므로 잘 보이게.
4. **가격 3티어 카드** — 스냅샷/구독/API를 비교 카드로. "월구독" 추천 강조. 단 "아직 결제 안 받음" 톤 유지.
5. **신뢰 섹션 상향** — 출처·라이선스·"no personal data"·갱신주기를 본문 신뢰 블록으로.
6. **폼 UX** — 1차(이메일+CTA) → 부가질문 점진 노출 검토. 제출 중 로딩/성공·에러 상태는 이미 구현됨(유지).
7. **반응형 다듬기** — 모바일에서 카드 여백·버튼·표 가독성.
8. (선택) 다크모드, 미세 애니메이션은 과하지 않게.

## 5. ⚠️ 깨면 안 되는 계약 (디자인 바꿔도 이건 유지/동기화)
디자인을 갈아엎어도 아래가 깨지면 **수집이 멈추거나 자동 테스트가 깨짐**. 변경 시 반드시 같이 업데이트.

**(a) 컬렉터 폼 계약** — JS가 `/submit`에 보내는 필드명/구조:
- `name="email"`(required, type=email), `name="persona"`, `name="need"`, `name="willingness"`, `name="product"`(영문은 hidden=fda), `name="hp"`(허니팟 — **반드시 시각적으로 숨김 유지**, 봇 방어).
- 제출 버튼 2개: `button[type=submit][data-intent="sample"]` / `[data-intent="presale"]`.
- `COLLECTOR_URL = "/submit"` (같은 도메인 상대경로 — CORS 회피).
- 제출 핸들러는 **응답 2xx일 때만** `#ok` 표시, 실패 시 `#err` 표시(버그#1 수정분 — 절대 되돌리지 말 것).

**(b) 상태 표시 요소 id:** `#ok`(성공), `#err`(실패) — 자동 테스트가 가시성으로 검증.

**(c) 언어 전환:** 영문에 `<a>한국어</a>`(→ `/ko/`), 국문에 `<a>English</a>`(→ `/`).

**(d) 내부 용어 금지:** 푸터·본문에 `§13-A`, `§7-b`, "선검증", "통과 기준" 등 **내부 게이트 용어 노출 금지**(바이어 신뢰 훼손). 전문 면책고지만.

**(e) 정직 카피 유지:** "verified"로 과장 금지(단일 출처). CC0·openFDA 출처·"no personal data" 유지.

**(f) 자동 테스트:** 셀렉터를 바꾸면 `browser-tests/run.mjs`(26 assertions)도 같이 수정. 변경 후 반드시 `cd browser-tests && node run.mjs` 통과 확인.

## 6. 산출물 기대 (클로드에게 요청할 때)
- 1~2개 디자인 방향 제안(가능하면 ASCII 와이어프레임/스니펫) → 고른 뒤 실제 `index.html`/`index.ko.html` 수정.
- 영문·국문 **양쪽 동기화**(구조 동일, 텍스트만 언어차).
- 외부 의존성 최소(정적 유지, 폰트는 시스템 or 1개 웹폰트까지). 빠른 로드·접근성 유지.
- 변경 후 `browser-tests/run.mjs` 통과 + 라이브 재배포(scp → /var/www/data.utilverse.info).
